NeonFlash

A high-performance, Redis-inspired in-memory data store with cyberpunk aesthetics

Overview

NeonFlash is a lightning-fast, minimalist, in-memory key-value store inspired by Redis. Written in Go for maximum performance, it establishes a TCP server on port 6379 and implements the Redis Serialization Protocol (RESP) for communication.

The architecture utilizes Go's powerful concurrency primitives with goroutines and mutexes to efficiently handle multiple client connections simultaneously. Perfect for projects requiring high-throughput, low-latency data access with a simple and familiar interface.

Installation & Setup

Prerequisites

  • Go 1.16+ installed on your system
  • Basic understanding of key-value stores
  • Redis client (optional for testing)

Installation Options

Method 1: Clone & Build from Source

git clone https://github.com/your-username/neonflash.git
cd neonflash
go build -o neonflash
./neonflash

Method 2: Using Go Install

go install github.com/your-username/neonflash@latest
neonflash

Method 3: Docker Container

docker pull yourusername/neonflash:latest
docker run -p 6379:6379 yourusername/neonflash:latest

Note: NeonFlash listens on TCP port 6379 by default. Ensure this port is available and not blocked by firewalls.

Configuration

NeonFlash currently runs with default settings. Future versions will support custom configuration via environment variables or a config file.

Usage

You can interact with NeonFlash using any Redis-compatible client. Here are some examples:

Using redis-cli

Connect to NeonFlash server and execute commands:

redis-cli -p 6379

Basic Operations

Ping the server:
redis-cli -p 6379 ping
PONG
Set a key-value pair:
redis-cli -p 6379 set user:1 "{"name":"Neo","level":42}"
OK
Get the value of a key:
redis-cli -p 6379 get user:1
"{"name":"Neo","level":42}"
Try to get a non-existent key:
redis-cli -p 6379 get unknown_key
(nil)

Programmatic Usage

You can use any Redis client library in your preferred language:

Go Example:

package main

import (
    "context"
    "fmt"
    "github.com/go-redis/redis/v8"
)

func main() {
    ctx := context.Background()
    
    rdb := redis.NewClient(&redis.Options{
        Addr: "localhost:6379",
    })
    
    err := rdb.Set(ctx, "cyberpunk:genre", "Neon, chrome, and digital dystopia", 0).Err()
    if err != nil {
        panic(err)
    }
    
    val, err := rdb.Get(ctx, "cyberpunk:genre").Result()
    if err != nil {
        panic(err)
    }
    
    fmt.Println("Value:", val)
}

Python Example:

import redis

r = redis.Redis(host='localhost', port=6379)
r.set('city', 'Night City')
value = r.get('city')
print(f"Value: {value.decode('utf-8')}")

Architecture

NeonFlash is designed with simplicity and performance in mind, following Go's concurrency patterns:

Core Components

  • TCP Server: Listens on port 6379 and delegates each client connection to a goroutine.
  • Connection Handler: Processes client requests using the RESP protocol parser.
  • In-Memory Store: Thread-safe global map protected by a read-write mutex.
  • RESP Protocol Implementation: Custom parser and writer for Redis protocol compatibility.

Code Structure

neonflash/
├── main.go           # Server initialization and request handling
├── resp.go           # RESP protocol implementation
├── store.go          # Key-value store operations (planned)
├── commands.go       # Command implementations (planned)
└── logging.go        # Enhanced logging system (planned)

Concurrency Model

NeonFlash uses a separate goroutine for each client connection, enabling efficient handling of multiple concurrent clients. The central data store is protected by a sync.RWMutex which allows:

  • Multiple simultaneous read operations
  • Exclusive access during write operations
  • Optimal performance for read-heavy workloads

Protocol Implementation

The RESP (Redis Serialization Protocol) implementation consists of:

  • Value Struct: Represents different RESP data types (strings, arrays, bulk strings, etc.)
  • RESP Reader: Parses incoming RESP-formatted data from clients
  • RESP Writer: Serializes responses back to the client in RESP format
