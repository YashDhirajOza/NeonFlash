NeonFlash

A Redis‑inspired in‑memory data store with futuristic neon vibes.

Overview

NeonFlash is a highly performant, minimalist, in‑memory key‑value store inspired by Redis. Written in Go, it sets up a TCP server on port 6379 and uses the RESP protocol for communication. The design leverages goroutines and mutexes to handle concurrent client connections efficiently.

Features

  • Redis-like Commands: Supports PING, SET, and GET.
  • RESP Protocol Handling: Custom parser and writer for arrays and bulk strings.
  • Concurrent Client Handling: Uses goroutines to manage multiple connections.
  • In‑memory Data Store: Global map protected by a read‑write mutex ensures safe data operations.
  • Neon-Themed Logging: Logs activity with visually appealing neon color effects.

Installation & Setup

Prerequisites

You need Go (version 1.16 or later) installed.

Clone & Build

git clone https://github.com/your-username/neonflash.git
cd neonflash
go build -o neonflash
./neonflash

Note: The server listens on TCP port 6379. Ensure your firewall settings allow traffic on this port.

Usage

You can interact with NeonFlash using Redis clients like redis-cli or any TCP client:

Ping the server:

redis-cli -p 6379 ping

Response: PONG

Set a key-value pair:

redis-cli -p 6379 set mykey "Hello, Neon World!"

Response: OK

Get the value of a key:

redis-cli -p 6379 get mykey

Response: "Hello, Neon World!"

Code Architecture

  • Server Initialization: The main.go file opens a TCP listener on port 6379, accepts connections, and handles each client in a separate goroutine.
  • Connection Handling: handleConn sets up a custom RESP parser and writer for each client request.
  • In‑memory Data Store: A global map protected by a read‑write mutex is used for safe concurrent access.
  • RESP Protocol: The resp.go file contains functions to parse arrays and bulk strings and marshal responses back to the client.
  • Logging: Detailed neon-themed logging provides insights into server activity.
